# Writing submission, feedback and revision workflow

This document describes the application workflow. Assignment prompts, learner responses and feedback examples in development data remain illustrative placeholders; they are not evidence of teacher review or educational approval.

## Assignment setup

1. An administrator opens a class group in the CMS.
2. In **Assigned writing tasks**, the administrator selects existing writing resources. No prompt or model answer is generated by this workflow.
3. The public class page displays only assigned writing resources whose parent resource is published and editorially visible.
4. A learner signs in and submits work from the class page. The submission is linked to that class group and writing assignment. An unassigned resource cannot be submitted through the class route.
5. A learner may also submit an individual writing activity outside a class. Those submissions remain private to the learner and administrators; they are not visible to a teacher through class review.

## Lifecycle and permitted transitions

| Current state | Action | Next state | Actor |
|---|---|---|---|
| draft | Submit | submitted | Learner |
| submitted | Start review | under_review | Owning class teacher or administrator |
| resubmitted | Start review | under_review | Owning class teacher or administrator |
| under_review | Publish rubric feedback | feedback_published | Owning class teacher or administrator |
| feedback_published | Request revision | revision_requested | Owning class teacher or administrator |
| revision_requested | Submit revised version | resubmitted | Learner |
| feedback_published | Mark complete | completed | Owning class teacher or administrator |

A learner can edit a draft or a revision-requested submission only. Submitted, under-review, feedback-published, resubmitted and completed work is locked. Saving a revision appends a new version; it never overwrites an earlier version. Each review is linked to the exact version it assessed. A revision request is only available after feedback has been published.

## Permissions

- Learners can list and open only their own submissions, versions and published feedback. Drafts are never visible to teachers.
- A teacher can list and review submitted work only for a class group whose `teacher_id` matches that teacher's account. Drafts are excluded from teacher lists and direct review routes.
- Administrators can review any class group.
- A class submission must reference an assignment attached to that class group. The class join code is an invitation to submit, not permission to read class submissions.
- Review endpoints re-check ownership and class-group association on every request. Hiding links in the interface is not an authorization control.
- The Filament writing-submission resource remains administrator-only and read-only. Teacher review uses the authenticated class web routes; teachers do not receive general Filament access.
- Feedback is inserted as published feedback only. There is no draft-feedback endpoint or learner-visible path to unpublished comments.

## Teacher rubric

Teachers score each criterion from 1 to 4 relative to the assigned task and the learner's CEFR level:

| Criterion | What the teacher considers |
|---|---|
| Task achievement | Whether the response fulfils the task, purpose and required points |
| Organization and coherence | Structure, paragraphing, sequencing and linking |
| Vocabulary and range | Appropriacy, range and control of vocabulary for the level |
| Grammar and accuracy | Range, control and intelligibility of grammatical forms |
| Spelling and punctuation | Mechanics and their effect on readability |

The scale is a teacher-facing scaffold: 1 Beginning, 2 Developing, 3 Effective, 4 Strong. These are not universal CEFR cut scores. Teachers must interpret each criterion against the actual task and level, and explain the judgement with actionable comments. The system does not calculate, infer or label an automated writing score. Overall feedback, strengths, improvements and next steps are stored with the criterion scores and publication timestamp.

## Learner instructions

- Save a draft while composing, or submit it when ready.
- After submission, the submitted version is locked while the teacher reviews it.
- Open **My Writing** to see status and published feedback.
- If a revision is requested, use the feedback and next steps, edit the response and submit again.
- Earlier versions and feedback remain available in the submission history.

## Retention and privacy treatment

Writing text, versions and teacher feedback are educational records and personal data. The application stores versions and reviews with the parent submission and does not introduce scheduled deletion, automatic anonymisation or a new retention period. Database constraints prevent deleting a class group or writing assignment while it has retained submissions; archive or unpublish it instead. The existing retention schedule remains proposed and requires controller and qualified Romanian/EU counsel approval before destructive automation. The migration that introduces version history snapshots each existing submission as version one; it does not change its status, create teacher feedback or imply approval of existing/dummy content.

No outbound notification is sent by this workflow. Learners see published feedback in their authenticated **My Writing** view. Do not add a new notification provider solely for this feature.
